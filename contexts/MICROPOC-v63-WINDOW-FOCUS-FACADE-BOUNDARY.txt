WINDOW FOCUS FACADE BOUNDARY

STATUS
VALIDATED

PURPOSE
Expose the v62-validated verified window focus through the public Computer Control facade without leaking backend or OS-specific implementation details.

ARCHITECTURAL INVARIANT
ComputerControl.focusWindow({app, window}) owns only the normalized public contract and application/window identity resolution.
The selected Desktop Plugin owns HOW focus is executed and HOW its postcondition is verified.
agent-ctrl remains private to the Desktop Plugin/backend boundary.

ID-FIRST CONTRACT
The public facade requires window.id and forwards only that stable id to the Desktop Plugin.
Observed title/focused/pinned metadata is not required for identity and is intentionally not trusted as an action selector. This preserves the v62/v63 finding that immediate post-focus title metadata may be stale/mismatched even when the stable id and physical focus are correct.

IMPLEMENTED SCOPE
- Public ComputerControl.focusWindow({app, window}).
- app required.
- stable window.id required.
- application Provider resolution.
- selected Desktop Plugin application identity resolution.
- routing only through desktop.focusWindow(application, {id:targetId}).
- plugin error/state/verification propagation.
- FOCUSED + verified returned only from the already validated Desktop Plugin result.
- public focusWindow export.
- v62 backend/plugin implementation preserved unchanged.

OBSERVED METADATA DEBT
The immediate post-focus window-list may associate the correct focused/pinned target id with the stale title of the previously pinned document. This was reproduced in both v62 and v63.
This does not invalidate focus because the stable id postcondition and independent physical observation agree.
The public action contract therefore remains id-first and must not use title metadata as an action selector.
Metadata consistency is separate debt and is not repaired in v63.
