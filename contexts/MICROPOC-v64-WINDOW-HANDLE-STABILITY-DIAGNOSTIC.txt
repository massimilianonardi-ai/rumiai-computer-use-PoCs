WINDOW HANDLE STABILITY DIAGNOSTIC

STATUS
WIP / PHYSICAL DIAGNOSTIC PENDING

PURPOSE
Determine whether macOS agent-ctrl window ids such as `pid:<pid>:window:<n>` are stable window identities or observation-scoped positional handles that can rebind when AX window ordering changes.

WHY THIS EXISTS
v62 and v63 physically focused the requested TextEdit document successfully, but immediately afterwards the same target id was reported with the title of the previously pinned document. That was initially classified as stale title metadata. Upstream source inspection now shows a stronger explanation: macOS agent-ctrl stores an `AxPinnedWindow { pid, index }`, enumerates the application's AXWindows array by index, and derives window ids from that pid/index pair. Therefore an id can denote a different concrete AX window if the array order changes.

UPSTREAM SOURCE FINDING
agent-ctrl commit inspected: 7cc6b3d6d25ae6064aa1cf56d32df3af6e24a212
File: crates/surface-ax/src/macos.rs
Observed implementation facts:
- AxPinnedWindow contains pid + index.
- list_windows() iterates AXWindows by array index and builds each WindowInfo id from that pid/index pin.
- focus_window(id) parses the id back to pid/index and raises the window currently at that index.

ARCHITECTURAL CONSEQUENCE IF CONFIRMED PHYSICALLY
The id is not a durable identity and must not be called stable.
It may be used as an immediate action locator only when paired with observation metadata and freshness validation.
Future action contracts must fail closed if an observed handle has rebound before use.

SCOPE
- No production code changes.
- No facade/plugin behavior changes.
- Add one test-only diagnostic harness.
- Open two distinct TextEdit windows.
- Observe the initial public window list.
- Select the unpinned target and preserve its initial id/title/process/pid mapping.
- Focus it using the currently validated public focus path.
- Observe the raw agent-ctrl window list after focus without a new target-process snapshot.
- Compare the original id->title mapping and the target title->id mapping after focus.
- Independently verify the physical front document.

DIAGNOSTIC SUCCESS CONDITION
The diagnostic passes if it obtains a coherent observation, regardless of whether ids remain stable or rebind. It must report one of:
- window-handle-stability=STABLE
- window-handle-stability=REBOUND
and physical focus must independently remain correct.

EXPECTED FROM EXISTING EVIDENCE
REBOUND is expected on current macOS/agent-ctrl because v62/v63 already showed the target id associated with the previous document title after focus.

NON-GOALS
- No fix in v64.
- No minimize/maximize/restore work.
- No change to v62/v63 historical physical PASS records.
- No claim yet about Windows/UIA id stability.

The diagnostic result must be committed before implementing the rebinding guard.
