RumiAI Computer Control micro-PoC v67
CLOSE WINDOW EPHEMERAL HANDLE DIAGNOSTIC

STATUS
VALIDATED / FALSE_NEGATIVE CONFIRMED

PURPOSE
Audit the existing macOS `closeWindow()` verifier against the v64 finding that agent-ctrl window ids `pid:<pid>:window:<index>` are ephemeral positional handles rather than durable identities.

WHY THIS EXISTS
The v59 close verifier captures a pre-close current-window id, sends Cmd+W, then takes a fresh application snapshot and considers close verified when:
- no fresh AX window is observable; or
- the fresh AX window id differs from the pre-close id.

That logic was physically valid for the original v59 single-window scenario, but v64 later proved that pid/index ids can rebind. With two windows, closing the front window can allow the surviving window to occupy the same `window:<index>`. In that case the physical close may succeed while the verifier observes the same positional id and reports UNVERIFIED.

PHYSICAL RESULT
macOS / TextEdit two-window fixture:
- front/closed fixture B before close: `pid:60698:window:0`
- survivor A before close: `pid:60698:window:1`
- public close returned `WINDOW_CLOSE_UNVERIFIED`
- independent document observation proved B was physically closed
- only A remained after close
- survivor A was then reported as `pid:60698:window:0`
- therefore the closed handle was reused by the survivor
- classification: `close-verifier-consistency=FALSE_NEGATIVE`
- diagnostic_exit=0

VALIDATED CONCLUSION
The v59 postcondition `afterId !== beforeId` is not valid in the multi-window case on current macOS/agent-ctrl because the id is a positional action handle, not durable window identity.

The historical v59 PASS remains valid for its original single-window scenario, but the verifier is not general enough for multiple windows.

ARCHITECTURAL CONSEQUENCE
Production close verification must not compare positional ids across the close operation.
A correct verifier must prove that the physical descriptor of the closed window is no longer present, or use an equally strong native OS-level postcondition that is independent of the rebinding handle.
