RumiAI Computer Control micro-PoC v60
WINDOW LIST OBSERVATION

STATUS
VALIDATED / macOS PHYSICAL PASS

PURPOSE
Implement the existing Desktop Plugin listWindows() contract on macOS as a read-only observation before exposing it through the public Computer Control facade.

ARCHITECTURAL INVARIANT
RumiAI defines the Desktop Plugin contract; the OS plugin owns HOW to obtain window observations.
agent-ctrl remains a backend/tool inside the macOS plugin and is not the public architectural API.

SCOPE
- Add backend agentCtrl.listWindows() using `agent-ctrl window-list --json`.
- Require valid JSON with a `windows` array.
- Mark macOS Desktop capability `window.list` IMPLEMENTED.
- macOS listWindows(application) explicitly pins the resolved application with a fresh read-only snapshot before enumeration.
- Normalize each returned window to:
  id
  title
  process
  pid
  focused
  pinned
- Keep ComputerControl facade unchanged in v60.

WHY THIS STEP
v59 demonstrated that cached current-window observation may be stale after a close while a fresh AX observation is authoritative. A first-class window enumeration primitive gives RumiAI a stronger observation basis for future focus/minimize/maximize/restore work.

UPSTREAM BACKEND CONTRACT CONFIRMED
agent-ctrl v0.1.4 documents `window-list` as the command for all top-level windows owned by the pinned process and supports `--json`. Its stable WindowInfo schema includes id, title, process, pid, focused and pinned. Its macOS AX fixture tests window-list physically.
