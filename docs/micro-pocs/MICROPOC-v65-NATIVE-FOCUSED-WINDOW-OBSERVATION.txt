RumiAI Computer Control micro-PoC v65
NATIVE FOCUSED WINDOW OBSERVATION

STATUS
VALIDATED / PHYSICAL PASS

PURPOSE
Validate a generic macOS observer for the actually focused window, independent of agent-ctrl's positional window pin. This observer is required before replacing the invalid v62/v63 post-focus verification exposed by v64.

ARCHITECTURAL CONTEXT
v64 physically proved that macOS agent-ctrl ids `pid:<pid>:window:<index>` are ephemeral positional handles and can rebind after focus. Therefore `target id pinned=true` cannot prove that the same physical window is focused after an action.

v65 does not change production focus behavior. It validates an OS-level observation primitive first.

OBSERVER VALIDATED
The final Swift helper uses:
- NSWorkspace.shared.frontmostApplication to resolve the application receiving keyboard events.
- AXUIElementCreateApplication(frontmost PID).
- kAXFocusedWindowAttribute to obtain the actual focused AX window.
- AXUIElementGetPid.
- kAXTitleAttribute.
- kAXIdentifierAttribute when available.
- `AXWindowNumber` custom attribute when available.
- NSRunningApplication for process/bundle diagnostics.

The original diagnostic attempt used AXUIElementCreateSystemWide() + kAXFocusedApplicationAttribute and physically failed with `kAXErrorCannotComplete (-25204)`. That exact FAIL was committed before correction. The helper was then corrected to resolve the frontmost application through NSWorkspace before querying AXFocusedWindow.

PHYSICAL RESULT
PASS on macOS 2026-08-24.
Observed before focus:
- process=TextEdit
- bundle=com.apple.TextEdit
- title=rumiai-v65-native-focus-B.txt
- pid=60394
- AXIdentifier=_NS:34
- AXWindowNumber absent

Observed after focusing fixture A:
- process=TextEdit
- bundle=com.apple.TextEdit
- title=rumiai-v65-native-focus-A.txt
- pid=60394
- AXIdentifier=_NS:34
- AXWindowNumber absent

The native observer matched the independent TextEdit front-document observation before and after focus.

IDENTITY FINDING
AXIdentifier `_NS:34` was the same for two different TextEdit windows, so it is not a unique per-window identity in this fixture.
AXWindowNumber was unavailable.
Therefore v65 did not discover a durable native window identity.

ARCHITECTURAL CONSEQUENCE
- agent-ctrl pid/index ids remain ephemeral action handles.
- AXIdentifier cannot be promoted to a stable RumiAI window id based on this evidence.
- AXWindowNumber cannot be relied upon because it was absent.
- The native focused-window observer is valid as an independent postcondition observer.
- Safe window actions must revalidate/re-resolve the observed window descriptor immediately before action and fail closed when identity is ambiguous or stale.

EVIDENCE

- tests/v65-macos-native-focused-window-observation-PASS.md

NON-GOALS
- No production focus fix in v65.
- No change to public facade/plugin/backend focus contract.
- No minimize/maximize/restore work.
- No claim that title is globally unique.
- No claim that macOS exposes a durable per-window AX identity.

NEXT
The next micro-PoC must replace unsafe id-only focus targeting/verification with a descriptor-aware fail-closed contract:
1. Treat observed id as an ephemeral handle, not identity.
2. Re-enumerate the target application's windows immediately before action.
3. Re-resolve the concrete current handle from the observed descriptor.
4. Fail closed on missing, changed, or ambiguous descriptor.
5. Verify the physical focused window with the v65 native observer, not with post-action `id pinned=true`.
